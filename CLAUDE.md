# Lexia — notes for Claude Code

Windows accessibility app for people with dyslexia (Linux on Ubuntu is planned for 1.0, stream J): press a hotkey, click or drag on a
frozen screenshot of the monitor, and the text there is OCR'd and read aloud. Works over
browsers, images, video and full-screen games. Languages: English only in 0.5 (ADR-0007), with no Language control in the UI; Bulgarian is in the code but not offered. Language support is planned for 0.8.

## Build (Developer PowerShell for VS, $env:VCPKG_ROOT set)

```powershell
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE="$env:VCPKG_ROOT\scripts\buildsystems\vcpkg.cmake" -DVCPKG_TARGET_TRIPLET=x64-windows
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure      # runs lexia_tests (doctest, tests/)
.\scripts\score_layout.ps1                                 # Fixture score vs tests\fixtures\baseline.json; exit 1 if any got worse
```

Output: `build\Release\lexia.exe`; package in `build\package\Lexia\` and `Lexia.zip`. With `-DLEXIA_INSTALLER=ON` (needs Inno Setup 6, `winget install JRSoftware.InnoSetup`) also
`build\package\Lexia-<version>-setup.exe` (H4: `installer\lexia.iss`, run by `cmake/installer.cmake` after the package step): a per-user install
by default (`%LOCALAPPDATA%\Programs\Lexia`; all users is offered), an optional Run at startup task, an optional Run as administrator task (K.7: its start state is `runAsAdmin` in the settings.json of the person who runs Setup; the choice is written after the install by `lexia.exe --set-run-as-admin on|off`, run `runasoriginaluser`), a running Lexia closed for the person (K.7, `installer\close_lexia.isi`, shared by Setup and the uninstaller: a Yes / No question, the registered message `Lexia.Quit` to the `LexiaApp` window, up to 10 s for the mutex to go, then an offer to end it by force with `taskkill`, with one UAC prompt for an elevated Lexia; silent runs never ask: Quit, wait, `taskkill` as the user, an elevated survivor stops the run), Start Lexia on the last page (it opens
its window and is Off), no runtime to install (the Settings window is native, ADR-0009; an update of 0.5 removes its old `ui\` folder and `WebView2Loader.dll`), and an uninstaller that
removes the Run value and asks about `%LOCALAPPDATA%\Lexia`. The installer's words are in the .iss (Inno Setup cannot read `strings/`).

clangd (the LSP tool): `.\scripts\compile_db.ps1` writes `build\clangd\compile_commands.json` (a Ninja
configure, nothing built; the VS generator can't), which `.clangd` points at. Re-run it after adding a
source file. clangd itself is LLVM's (`C:\Program Files\LLVM\bin`, must be on PATH).

**Ending Lexia** (D2): `lexia.exe` is a Windows (GUI) program with no console; it lives in the tray. Right-click the tray icon, then Quit: `App::Quit()` ends `App::Run`, which stops speech, releases the keys, closes the Settings window and removes the icon (a clean exit). Open Lexia in that menu, or a double-click on the icon, opens the Settings window; closing the window does not end Lexia. Only one Lexia runs: a second launch asks the first to open its Settings window and exits. Run as admin (D8.3, ADR-0008): with `runAsAdmin` on and Lexia not elevated, `wWinMain` lets go of the mutex, starts `lexia.exe --elevated-relaunch` (plus `--minimised` if it was) with the `runas` verb (UAC prompt) and ends; the new one waits up to 5 s for the mutex. A cancelled prompt, or any failure, is logged and Lexia goes on unelevated. Turning the switch on in the Settings window relaunches in the same way and ends the old instance with `Quit()`; the Run key value is unchanged, so with the switch on every logon shows the UAC prompt. At start the Settings window opens (and comes to the front) unless Lexia was started with `--minimised`. Run at startup writes `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Lexia` = `"<exe>"`, plus `--minimised` when Start minimised is on (D9: the switch under run at startup, on by default, usable only while run at startup is on), so a start at logon stays in the tray or opens the window, and a manual start always opens the window; every start writes the value again (this exe's path, the switch as the setting says). The elevated relaunch passes the foreground on (`AllowSetForegroundWindow`), so its window comes to the front. On / Off is Off on the very first start (no settings.json) and remembered after that. The Settings window is a fixed 800 x 600 DIPs, not resizable, with no Windows title bar (K10: it has its own minimise and close buttons, and bare paper drags it). For development run `lexia.exe --console`: it opens a console (log lines and recognised text print there, Ctrl+C works). Ctrl+C or closing that console ends Lexia through Windows' default handler (`ExitProcess`): the keys are released by the system, but the shutdown in `App::Run` does not run, so speech is cut off; use the tray Quit for a clean exit. If Lexia cannot start (OCR models missing) a message box says so, as there is no console to read it in. Turning Lexia Off (tray, Home, or `"enabled": false` in settings.json) frees every key without ending it. The exe carries an application manifest (`src/lexia.manifest`: PerMonitorV2, Common Controls 6, UTF-8 active code page, Windows 10/11) added by CMake, and the tray icons `src/res/lexia.ico` (On, also the exe icon) and `lexia_off.ico` (the Off look), made from the owner's logo SVGs (a design on the public-domain Old Book Illustrations engraving "Faust—Scene III Headpiece") `src/res/lexia_logo.svg` (On) and `lexia_logo_off.svg` (Off: the engraving faded, with a muted speaker) by `scripts\make_tray_icons.ps1` (K12; 16, 20, 24, 32, 48, 64 and 256 px PNG frames, drawn by the dev tool `lexia_svgshot`, Direct2D; committed; rerun only when a logo file changes).

`lexia_barshot` is built too (`build\barshot\Release`, not packaged): `lexia_barshot.exe --size large|small --state idle|speaking|paused|analysing [--hover pause|skip|stop|help|size] [--theme light|dark] [--dpi N] out.png` writes the picture of the Control bar as `controlbar.cpp` draws it (shadow margin of 32 px at 96 dpi), to compare with `wireframe\control_bar_*.png`.

`lexia_svgshot` is built too (`build\svgshot\Release`, not packaged; K12): `lexia_svgshot.exe --px N in.svg out.png` draws one SVG file at N x N pixels with Direct2D (`DrawSvgDocument`, the renderer the app uses) on a transparent background and writes a PNG (straight alpha, WIC). It has no resources and shares no code with `lexia.exe`; `scripts\make_tray_icons.ps1` runs it for the icon frames (System.Drawing cannot read SVG).

`lexia_settingsshot` is built too (`build\settingsshot\Release`, not packaged; K.1c): `lexia_settingsshot.exe --page gallery|home|voices|settings|report|help|about [--on] [--hover power|enable|home|...|minimise|close|mail|discord|github|itch|notices|volume|delete|download|addfile|speed|pitch|volume|reset-pitch|save|load] [--voices none|changed|user] [--sheet delete|deleteFailed|catalogue|offline|downloading|done|failed|failed-baddownload|added|refused|refused-notmedium|presetSaved|presetLoaded|presetFailed] [--select read|pause|speech|readAlong|runAtStartup|startMinimised|runAsAdmin|darkMode|leftHanded] [--capture read|pause|speech] [--switches] [--reading] [--theme light|dark] [--dpi N] out.png` draws a page of the native Settings window off-screen (800 x 600 DIPs, the same widget tree and `D2dCanvas` as the window; WARP is enough) and writes a PNG, to compare with `wireframe\html-reference\`; it prints `colours=N` (distinct colours). `gallery` is every toolkit control in its states (hover forced with `Widget::PreviewHover`, press and keyboard focus through `Screen`); the six real pages are the real `SettingsUi` (frame + page) on the sample `UiState` of `src/settingsshot_sample.*` (the values of the old mock host; `--on` = Lexia On); pages are in `src/settingsshot_pages.*` (`BuildShotPage`; K.3 added `--voices` (the Voices page's sample variants: `none`, `changed` = pitch off the default, `user` = the Voice a person added is active) and `--sheet` (the three sheets with the data of the old mock host's `?sheet=`, fed through the same `VoiceEventSink` the window uses; the `SettingsUi` is kept alive for the sheets' callbacks); K.4 added `--select` / `--capture` / `--switches` for the Settings page; K11 `--reading`: the card that `--select` shows (the first Key by default) is being read aloud, so its read button shows the stop icon `volume-07`, and `settings_shots.ps1` writes `settings-reading`); `settingsshot_sample.*` also has `SampleCatalogue()`. `.\scripts\settings_shots.ps1 [-Dpi N]` writes every finished page, light and dark, to `build\settingsshot\pages\` with the file names of `wireframe\html-reference\`. ctest `settingsshot_smoke` draws the gallery light and dark and fails if a PNG is missing, small or one plain colour.

`lexia_cli` is built too, into its own folder so its extra DLLs stay out of the package:
`build\cli\Release\lexia_cli.exe <shot.png> [--lang en|bg] [--rect x,y,w,h] [--json out.json] [--draw out.png] [--score expected.txt]`.
It runs the app's OCR + layout on a saved Shot; no flag prints the Blocks' text (the `expected.txt`
format; `--score` prints the Fixture score as one line of JSON). It finds models beside itself, else
in the dev `models\` folder. Not packaged. `score_layout.ps1` takes `-Cli <exe>` (default
`build\cli\Release`), `-Tolerance` (default 0.02 on the normalised distance; the Block-count error
may not rise at all) and `-SaveBaseline` (rewrites the baseline: say why in the PR).
The Settings window is drawn by `lexia_settingsshot` (above); `.\scripts\settings_shots.ps1` writes every page to `build\settingsshot\pages\` to compare with `wireframe\html-reference\` (the shots of the old HTML pages, the layout spec; their colours are the old ones) and with the owner's mockups `wireframe\<page>.png` / `<page>_dark.png` (the colours, K13). The colour pairs are checked by ctest `palette_test` (`tests/palette_test.cpp`; the colours are in `src/native_ui/palette.cpp`): text 4.5:1, edges and states 3:1.
Generator: Visual Studio 18 2026. CMake 4.4. C++17. vcpkg manifest mode.

Optional signing: `-DLEXIA_SIGN=ON` Authenticode-signs `lexia.exe` and `piper.dll` in the package folder before the zip
(`cmake/sign.cmake`; `signtool` from the Windows SDK; certificate by env `LEXIA_SIGN_THUMBPRINT`, or `LEXIA_SIGN_PFX` +
`LEXIA_SIGN_PFX_PASSWORD`; never cached). OFF by default and in CI. See `docs/signing.md`.

Not in git (fetch with `powershell -ExecutionPolicy Bypass -File scripts\fetch_deps.ps1`):
- `onnxruntime\` — prebuilt ONNX Runtime zip (include\, lib\)
- `models\` — det.onnx, rec_en.onnx, dict_en.txt, rec_cyrillic.onnx, dict_cyrillic.txt
- `voices\` — the Piper Voice files listed in `voices\voices.json` (`bg_BG-dimitar-medium` is for local testing only, never packaged; Bulgarian is not offered, ADR-0007)

Piper is not fetched: the first build clones piper1-gpl and espeak-ng at pinned commits and builds
`piper.dll` into `build\lp_install` (CMake `libpiper_external`; needs the network and a short build path).
`lexia_cli --say "text" --lang en|bg --wav out.wav` speaks to a WAV file. `--speed`, `--pitch`, `--volume` set the Voice controls for it.
Voice library (B5, the only network use, and only when you run it): `lexia_cli --voices-catalogue` lists the downloadable Voices (Hugging Face
`rhasspy/piper-voices`, for Lexia's Languages, Medium only); `--voice-download <name>` fetches one and checks size and MD5; `--voice-add <file.zip|.onnx|.onnx.json>`
adds one from disk. Both write to `%LOCALAPPDATA%\Lexia\voices` unless `--voices-dir <folder>` says otherwise.

## Rules

- **Never take focus in the overlay.** It must stay `WS_EX_NOACTIVATE`: full-screen games
  minimise when they lose focus. Don't "fix" keyboard input going to the game by activating it.
- Keep `layout.*` free of Win32 and ONNX so it stays unit-testable.
- Text is UTF-8 in `std::string` internally; convert to UTF-16 only at Win32 boundaries.
  Source files are UTF-8 (compiled with `/utf-8`).
- Zero compiler warnings at `/W4`. Don't silence a warning without a comment saying why.
  CI (`.github/workflows/ci.yml`) builds Release with `-DLEXIA_WARNINGS_AS_ERRORS=ON` (`/WX` on Lexia's own
  targets; OFF by default), runs `ctest` and `score_layout.ps1`. `vcpkg.json` pins `builtin-baseline`: bump it on purpose.
- Any change to grouping/reading order must run the fixture score before and after and report both.
  No fixture may get worse beyond the tolerance in `scripts/score_layout.ps1`.
- Text the user sees or hears (hint bar, Announcements, Control bar, tray, Settings window) goes through `strings/`, never a literal in the code.
- **British English everywhere** (owner, Nov 7): UI text (`strings/table_en.cpp`), the installer, docs and comments ("minimise", "colour", "analyse", "recognise"). Identifiers and keys that come from other APIs or older files keep their spelling (`SC_MINIMIZE`, `hoverColor` in settings.json, `RecognizeBlocks`).
- Diagnostics go through the logger (`log.h`, P0.7), not `std::cout`.
- New dependencies go in `vcpkg.json`; check the licence first and add it to the package's
  third-party notices (`licenses/components/`, see `docs/third-party.md`).
- Lexia is GPL-3.0-or-later (`docs/adr/0003-gpl-3-licence.md`): every dependency, and every
  shipped voice, must have a GPL-3-compatible licence.
- A change that implements or changes a plan item (a task id, an R-finding) updates `docs/Lexia — Code Review & Agent Plan.md`
  in the same PR: tick the task, fix its status, the "Status" section and the milestones, mark an R-finding fixed.
  The "Plan" section below must say the same (what is merged, what is open).
- **Use clangd for C++.** Navigate and review C++ with the LSP tool (clangd): definitions, references,
  hover, call hierarchy, symbols. Cross-check references with Grep until the index is complete. Run
  `.\scripts\compile_db.ps1` after you add a source file. This applies to every subagent too.
- **Use Security Guidance when you plan code.** The Security Guidance plugin (Anthropic directory) must be
  enabled while you plan and write code; if it is missing, ask the owner to install it. Each code plan has a
  Security section (input from files, network only on request (ADR-0005), path traversal, DLL search path,
  COM and UI Automation lifetimes, links only from `LinkUrl`).
- One task per branch (`feat/<task-id>`), one task per PR. Stop at the task boundary and summarise:
  what changed, how it was verified, what the owner must check by hand.

Anything visual or audible, and behaviour inside games (Undertale is the reference title). End
each task with a short manual test list for the owner rather than claiming it works.
