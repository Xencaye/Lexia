## Voices

Voices are separate data files in `voices/`, listed in `voices/voices.json` (with their pinned download source (the list's `source`, or a `source` of one Voice that replaces it), SHA-256 and a `ship` flag). `scripts/fetch_deps.ps1` fetches them (https only, each file checked against its SHA-256); the package step copies only the ones marked `"ship": true`. The licence research is in task B6.

- **English: `en_GB-cori-medium` (the default), the only shipped Voice** (B13, owner Nov 17; B14, owner Nov 19: `en_US-norman-medium` stopped shipping, see the next point). The default is the first English Voice in `voices.json`. Cori is Bryce Beattie's OLD model, the copy in `rhasspy/piper-voices` at commit `5041a7a49ae5b3a0f30e6837769eb03fdbb231bd` (SHA-256 of the `.onnx` `1899F98E…F10D`); `voices.json` gives it its own `source`; the list's `source` (`cf910fb`, 2026-11-09) is the default for an entry without one. Cori is trained from scratch by Bryce Beattie on LibriVox recordings (public domain), so it does not come from `lessac`. No Voice has a licence line of its own for the model weights; the repository `rhasspy/piper-voices` is tagged MIT and Piper's `docs/VOICES.md` says it imposes no restrictions on voice models. `en_US-lessac-medium` and every voice fine-tuned from it must not be shipped (the Blizzard 2013 Lessac data is research-only). Cori is final (owner, Nov 19): the owner does not pick another shipped Voice.
- **Not shipped any more:** `en_US-norman-medium` (B14, owner Nov 19: it mispronounces too much; trained from scratch by Bryce Beattie on LibriVox recordings, public domain). Its licence entry is no longer in the package notices, and the Download sheet does not list it. An update keeps its files as one of the user's own Voices (`AdoptRetiredVoices`, B9). `en_US-ljspeech-medium` (B13; trained from scratch on the LJ Speech Dataset by Keith Ito, https://keithito.com/LJ-Speech-Dataset/, public domain). An update keeps its files as one of the user's own Voices (`AdoptRetiredVoices`, B9), so its settings and Presets keep working, and it is on the Download sheet's list. Its licence entry is no longer in the package notices, because Lexia does not ship it. Also not shipped: the NEWER `en_GB-cori-medium` of `cf910fb` (base `hifi_tts_92`, CC BY 4.0) and `en_US-mike-medium` (B8, 0.7 test builds only): they mispronounce common words such as "library", "anonymized" and "account" (espeak-ng gives the right phonemes; the models say them badly). `en_GB-jenny_dioco-medium` and `en_US-joe-medium` were tried too (B10): their `cf910fb` versions (from the clean `hifi_tts_92` and `rdh` bases) sound worse than their old `lessac` versions, which must not ship.
- **The Download sheet** (Voice library, B12) offers a short list that the owner picked and that is compiled into Lexia (`src/tts/download_list.cpp`): `en_US-kristin-medium`, `en_US-john-medium` and `en_US-ljspeech-medium`, all at the commit `cf910fb` of `rhasspy/piper-voices`, so a downloaded Voice is the version the licence notes describe. Lexia fetches no catalogue; opening the sheet makes no request. All three have public domain recordings (Kristin and John: LibriVox; LJ Speech: the LJ Speech Dataset of Keith Ito) and no non-free base (Kristin and LJ Speech from scratch, John from Kristin), so no credit is required (`docs/notes/voice-download-list.md`). Lexia does not distribute them: the user's PC downloads each file after the user asks. A Voice that needs a label or a credit gets one when the owner adds it (B12.4). The shipped Voice of a name wins in the Voice list (`ListInstalledVoices`); the list holds no Voice of a shipped name.
- **Bulgarian: no Voice.** Bulgarian is not offered (ADR-0007); its Voice is to be the owner's own (E6).
- **A copy of each Voice model gets one extra graph output at run time** (word timings for the read-along, `src/tts/onnx_alignment.*`). Lexia appends one `output` entry (the model's own `w_ceil` tensor) to the graph of the ONNX file, as Piper's `patch_voice_with_alignment.py` does. The weights and every other byte are unchanged. The copy is written to `%LOCALAPPDATA%\Lexia\aligned` the first time the Voice is loaded (about 60 MB for a Medium Voice), stays on the user's PC and is never shared or uploaded; the Voice file in `voices` is not touched. It is removed when the user deletes the Voice, and with the Lexia data folder when the uninstaller is asked to remove it. The Voice licences above allow this: none forbids a derived copy for the user's own use, and the copy is not distributed.

## The package's notices

`build\package\Lexia\` (and `Lexia.zip`) holds `LICENSE` (Lexia's GPL-3.0-or-later text, copied from the repository root), `THIRD-PARTY-NOTICES.txt` and `licenses\onnxruntime-ThirdPartyNotices.txt` (ONNX Runtime's own list of what its binary contains). `cmake/package.cmake` makes `THIRD-PARTY-NOTICES.txt` with `cmake/notices.cmake` from the files in `licenses/`:

- `licenses/header.txt` is the top of the file.
- `licenses/components/<name>.txt` is one component, in file-name order. The first line is its title. It gives the name, version where known, licence, copyright holders, source and what Lexia uses it for. Lines that start with `@` are directives:
  - `@include <file>` puts that file's text in as it is. `{ORT_DIR}`, `{SOURCE_DIR}` (the source tree, always set; for the font's and the icons' own licence files), `{VCPKG_SHARE}` (vcpkg's `share\` folder, where each port's `copyright` file is), `{PIPER_SRC}` and `{ESPEAK_SRC}` in the path are replaced by the build's folders. Prefer this to retyping a licence: the text then follows the version that is built.
  - `@licence-text <id>` refers to `licenses/texts/<id>.txt`, which is printed once at the end under LICENCE TEXTS however many components use it.
  - `@ship <file> [as <name>]` copies a long file to `licenses\` in the package instead of repeating it.
  - `@covers <name>...` says which `.exe` / `.dll` files in the package this entry is the licence for (`*` is a wildcard).
- `licenses/components/voice-<Voice name>.txt` is the entry for a Piper Voice. It is used only when `voices/voices.json` has `"ship": true` for that Voice.

The package step fails (so does the build) when a Voice with `"ship": true` has no `voice-<name>.txt`, and when a `.exe` or `.dll` in the package is covered by no `@covers` line. The ctest `package_notices` (`tests/notices_test.cmake`) checks both.

To add a component:

1. Check its licence is GPL-3-compatible (ADR-0003) and add a row to the table above.
2. Add `licenses/components/<name>.txt`. Take the licence text from the vcpkg port's `copyright` file or the component's own source with `@include`, or add the text to `licenses/texts/` if it is a standard one (the SIL OFL for a font, for instance) and refer to it with `@licence-text`. If the component brings a DLL, add `@covers` for it. Fonts and other data files are not checked by `@covers`; name them in "Used for".
3. Build and read `build\package\Lexia\THIRD-PARTY-NOTICES.txt`.

A new Voice: add its `voice-<name>.txt` (the wording for each kind of Voice is in `docs/notes/voice-licences.md`, section 5) before setting `"ship": true`.

Not covered by `@covers`: the OCR models, `espeak-ng-data\` and the Voice files are data. Their entries (`paddleocr-models.txt`, `espeak-ng.txt`, `voice-*.txt`) are written by hand.
